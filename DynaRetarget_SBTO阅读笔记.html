DynaRetarget: Dynamically-Feasible Retargeting using Sampling-Based Trajectory Optimization

用采样轨迹优化（SBTO）+ 增量式 horizon 扩展，把 IK 得到的运动学可行人类轨迹，转换成真正物理一致、动力学可行的人形机器人轨迹。IK 不是最终答案，而是 warm start。

Victor Dhédin · Ilyass Taouil · Shafeef Omar · Dian Yu · Kun Tao · Angela Dai · Majid Khadiv MRM / TUM
01 论文速览

这篇论文解决什么问题？核心思路是什么？

核心问题
IK retargeting 只保证 运动学可行（关节限位、姿态匹配），不保证 动力学可行（接触、摩擦、平衡、物体交互）。
传统方法的坑
① missing contact（脚/手没碰对位置）
② foot/object penetration（穿模）
③ 机器人站不稳、无法真实执行
核心思路
SBTO = Sampling-Based Trajectory Optimization
在 IK 结果基础上做物理优化
增量式 horizon 扩展 + CEM 采样搜索

03 四大核心模块

拆解 SBTO 方法的每个关键组件。

M1

Optimal Control 建模

把轨迹优化建成标准最优控制问题：

min J(x,u)，约束为动力学方程 x(t+1) = f_dyn(x(t), u(t))

状态 x = 关节位置 + 速度；控制 u = PD target trajectory（不是直接力矩）。整个仿真器是个黑盒，用 PD controller 驱动。
  • 无梯度，只能用 zero-order / sampling 方法
  • 人形机器人：高维 + 非凸 + 接触丰富
  • 因此选 sampling-based 而非 gradient-based
M2

CEM 采样优化

Cross-Entropy Method，用 Gaussian distribution 搜索 control knots：

k ~ N(μ, Σ)
μ = 当前搜索中心；Σ = 搜索范围和变量相关性

迭代流程：采样 → 插值成完整轨迹 → 仿真 rollout → 算 cost → 选 elite → 更新 μ 和 Σ。
  • Sample 的不是 state，是 control knots
  • Simulator 根据 control 产生真实 state
  • EWMA 平滑防止过早收敛
M3

Incremental Horizon（核心创新）

不一次优化完整轨迹，而是从短到长逐步扩展：

0 → 0.5s → 1s → 2s → full trajectory

每个阶段用上一阶段结果 warm start。SBTOskip 机制：当某个 horizon 的变量已经收敛，就跳过不重复优化，节省计算。
  • 降低长时程搜索难度
  • 保留长期目标，不像 SBMPC 那样短视
  • SBTOskip：收敛的变量跳过不优化
M4

Cost Function 设计

Cost 定义什么是"好的轨迹"，五大类：

① Motion Tracking：关节位置/速度误差
② Task Space Tracking：躯干、脚、手姿态（因为人/机器人结构不同）
③ Object Tracking：物体位置/方向/速度
④ Regularization：平滑度、关节限位
⑤ Collision：自碰撞 + 物体碰撞惩罚
  • Task space 比 joint space 更符合任务需求
  • Object tracking 权重很高（40）
  • Collision cost 来自 MuJoCo
04 SBTO 核心：增量式 Horizon

为什么不能一次优化完整轨迹？Incremental Horizon 怎么工作？

优化过程：从短 horizon 逐步扩展
每个阶段用上一阶段结果 warm start，逐步扩展到完整轨迹

为什么 FHTO（Fixed-Horizon TO）不行？

长时程人形动作搜索空间巨大，一次优化所有 control 变量很容易：
① 采样质量差，大部分样本都是烂的
② 优化卡在局部极小出不来
③ 前面的节点没收敛，后面的节点白优化

SBTO 的解法：先优化前 0.5 秒（简单问题），收敛后再扩展到 1 秒，再 2 秒……每一步都是在上一步的好解附近微调，难度大幅降低。这就是 warm start 的威力。

实验结论解读

SBTO vs IK：动态一致性大幅提升，IK 轨迹基本站不住，SBTO 生成的轨迹可以直接用来训练 RL policy。

SBTO vs FHTO：FHTO 长 horizon 优化不下来，SBTO 靠 incremental warm start 解决了。

SBTO vs SBMPC：SBMPC 是短视的（myopic），每次只看前面一小段；SBTO 有长期视野，能规划完整动作。

Feasible ≠ Optimal：SBTO 生成的是"物理可行"的轨迹，不是"最优"轨迹。它的目标是让机器人真的能做出来，而不是做得最优雅。

Sampling-Based Trajectory Optimization，采样式轨迹优化
CEM
Cross-Entropy Method，用 Gaussian 分布采样搜索的优化方法
FHTO
Fixed-Horizon Trajectory Optimization，一次优化完整轨迹
SBMPC
Sampling-Based MPC，短 horizon 模型预测控制，短视
Incremental Horizon
从短到长逐步扩展优化范围，warm start 每一步
Kinematic vs Dynamic Feasible
前者几何上摆得出来；后者物理上真的能做出来
Control Knots
CEM 采样的对象：分段控制关键点，插值成完整轨迹
